# Yggdrasil Watchdog (Windows) - инструкция

## Что это

То же самое, что и Linux-версия, но полностью на C++ (без Python -
на этой машине Python доступен только через Windows Store алиасы,
которые несовместимы с Планировщиком заданий). Один `.exe`, никаких
внешних зависимостей кроме стандартных библиотек Windows.

## Что работает автоматически, без твоего участия

Раз в 3 минуты Планировщик заданий запускает проверку (`tick`) от
имени `SYSTEM` - работает независимо от того, вошёл ли ты в систему,
и не показывает никаких окон (сессия 0, изолированная от рабочего
стола):

- **Аварийный режим по батарее** проверяется первым делом - если
  заряд ≤5% и ноутбук не на зарядке, все остальные проверки этого
  тика пропускаются целиком (одно уведомление на вход, одно на выход)
- Раз в сутки - тихая проверка обновлений на GitHub (только
  уведомление, ничего не скачивает сама)
- Если все основные пиры легли - ищет замену: сначала в egress-регионе
  (определяется автоматически по IP через GeoIP, кэш на час - корректно
  учитывает VPN, если он держит маршрут по умолчанию), иначе в домашнем
  регионе (ручной fallback), проверяет кандидата настоящим рукопожатием,
  добавляет как резервного
- Если обычный поиск не помог - крайняя мера: аварийный (SOS) перебор
  ВСЕХ пиров ВСЕХ стран, ограниченный по времени за один тик,
  возобновляемый (следующий тик продолжает с того же места), с
  12-часовой паузой после полного прохода без результата
- Как только основной снова жив - резервные убираются
- Если включён региональный режим - следит за региональными пирами
  вместо основных
- Если пропал интернет вообще - не тратит время на бессмысленный
  поиск, ждёт восстановления
- Если связь в порядке - проверяет добавленные вручную устройства
  (ноутбуки); при подтверждённой недоступности проверяет, не сам ли
  Yggdrasil на этой машине перегружен (а не нагрузка машины вообще),
  и если да - перезапускает службу
- Задача сама настроена срабатывать сразу при пробуждении из сна,
  если пропустила тик во время сна (`StartWhenAvailable`)

Проверить, что задача жива:
```
schtasks /Query /TN "YggWatchdogTick" /V /FO LIST
```
Ищи `Scheduled Task State: Enabled` и `Status: Ready`.

## Файлы проекта - должны лежать вместе, в одной папке

| Файл | Назначение |
|---|---|
| `ygg_watchdog.cpp` | Исходник - вся логика, один файл |
| `cities.dat` | База городов GeoNames с координатами (обязателен) |
| `notify.conf` | Токен/chat_id для уведомлений в Telegram (необязателен - без него уведомления просто выключены) |
| `run_ygg_watchdog.bat` | Собирает `.exe` из исходника (если нужно) и запускает |
| `app.rc`, `ygg-watchdog.ico` | Иконка программы, вшивается в `.exe` при сборке |
| `ygg_watchdog.exe` | Готовая программа (или появится после сборки батником) |
| `watchdog.log` | Лог - появится после первого запуска |
| `state.txt` | Файл состояния - появится после первого запуска |
| `vpn_hook_approval.txt` | Одобренный VPN-скрипт и его SHA-256 (появится после `approve-vpn-command`) |

## Установка

Скачай из этой папки `ygg_watchdog.exe`, `cities.dat` и `notify.conf.example`, положи их в одну постоянную папку (например `C:\Tools\ygg-watchdog`), дважды кликни `ygg_watchdog.exe` и в меню выбери пункт **2**, чтобы установить задачу планировщика.

Не переноси папку после установки задачи: планировщик запоминает путь к exe. Если перенёс, снова выбери пункт 2.

Если антивирус (Защитник Windows) блокирует программу или мешает ей подключаться к пирам - добавь папку программы в исключения (Безопасность Windows → Защита от вирусов и угроз → Управление настройками → Исключения → Добавить исключение → Папка). Сама программа доступ к фаерволу/антивирусу не трогает и не настраивает - только предупреждает в логе, если похоже, что дело в блокировке.

## Сборка из исходника / пересборка после обновления

```
run_ygg_watchdog.bat
```

Если `.exe` не существует или исходник (`ygg_watchdog.cpp`) новее уже
собранного `.exe` - соберёт заново сам (ищет `g++`, потом `cl`, потом
пытается найти Visual Studio автоматически; для SHA-256 используется
встроенный в Windows `bcrypt.lib`, дополнительно ничего ставить не
нужно). После пересборки **обязательно** зайди в меню и выбери пункт
2, чтобы переустановить задачу планировщика - без этого Планировщик
продолжит использовать дату/настройки старой версии задачи.

## Меню

Двойной клик по `ygg_watchdog.exe` (или по `run_ygg_watchdog.bat`)
открывает меню:

```
================================================
        YGG WATCHDOG
================================================

  1 - Проверить сейчас (tick)
  2 - Установить/переустановить задачу автозапуска
  3 - Остановить задачу автозапуска (удалить из планировщика)
  4 - Показать основные пиры
  5 - Убрать региональный режим (вернуться на основные пиры)
  6 - Перезапустить службу Yggdrasil сейчас (обрыв связи по Yggdrasil!)
  7 - Задать домашний регион (постоянный fallback для резервных пиров)
  8 - Список устройств для мониторинга
  9 - Добавить устройство для мониторинга
  10 - Удалить устройство из мониторинга
  11 - Одобрить VPN-скрипт (продвинутый режим)
  12 - Снять одобрение VPN-скрипта
  13 - Проверить обновления на GitHub
  14 - Скачать и применить обновление
  0 - Выход
```

При первом запуске каждой команды спросит права администратора через
UAC - это ожидаемо (нужны для доступа к `yggdrasilctl` и Планировщику).

### Пункт 1 - Проверить сейчас
То же самое, что делает Планировщик каждые 3 минуты, но сразу.

### Пункты 2-3 - Задача планировщика
- **2**: установить/переустановить (нужно один раз при первой
  установке, и повторно - после каждой пересборки `.exe`)
- **3**: полностью снять с Планировщика - автоматические проверки
  прекращаются до повторной установки

### Пункт 4 - Основные пиры
Список из `yggdrasil.conf`. Добавление/удаление основного пира и
региональный режим (добавление нового региона) в меню не вынесены -
делаются через команды напрямую (см. ниже), региональный режим
снимается пунктом 5.

### Пункт 5 - Убрать региональный режим
Снимает все региональные пиры разом, возвращает обычный режим.

### Пункт 6 - Перезапуск службы Yggdrasil
Сразу. Если подключён к этому компьютеру через сам Yggdrasil
(например RDP по Yggdrasil-адресу) - соединение оборвётся в процессе.
Для отложенного перезапуска (чтобы успеть отключиться) используй
команду напрямую: `ygg_watchdog.exe restart-yggdrasil-delayed 15`.

### Пункт 7 - Домашний регион
Постоянный ручной fallback для поиска резервных пиров - используется,
только если автоматическое определение egress-региона через GeoIP не
сработало (нет сети наружу, сервисы недоступны). Покажет список стран
и попросит номер; пустой ввод снимает домашний регион.

Как и в региональном режиме, выбирается страна, а затем город из базы
(Enter - любой город страны). Если город задан и резервные ищутся в
этой же стране, первыми проверяются пиры, ближайшие к нему по
координатам.

### Пункты 8-10 - Устройства для мониторинга
Добровольно добавленные ноутбуки (не телефон), проверяются только
после подтверждённой основной связности:
- **8**: список с текущим статусом
- **9**: добавить (спросит имя и Yggdrasil-адрес/IP)
- **10**: удалить (покажет список, спросит имя)

### Пункты 11-12 - VPN (продвинутый режим)
По умолчанию программа в VPN-клиент не лезет вообще, только
предупреждает в логе, если похоже, что проблема в нём. Чтобы включить
автоматический перезапуск VPN своим скриптом:
- **11**: одобрить скрипт (укажи полный путь) - сохраняется путь и
  SHA-256 содержимого; перед КАЖДЫМ запуском хэш пересчитывается и
  сверяется, при любом изменении скрипта запуск отказывается
- **12**: снять одобрение, вернуться на базовый уровень

### Пункты 13-14 - Обновления
Программа и сама, раз в сутки, тихо проверяет GitHub и только
уведомляет, если есть новая версия - ничего не скачивает
автоматически:
- **13**: проверить вручную прямо сейчас
- **14**: скачать готовый `.exe` из релиза и поставить его - новый
  файл сначала проверяется (что это рабочий `.exe`), текущая версия
  сохраняется как `ygg_watchdog.exe.backup`, замена происходит через
  несколько секунд после закрытия этого запуска. Если новая версия
  вообще не запустится - переименуй `.backup`-файл обратно вручную.

**Правки основных пиров вступают в силу только после перезапуска
службы** (пункт 6 или `restart-yggdrasil-delayed`).

## Уведомления в Telegram

Присылает push-уведомления о значимых событиях:

- **Все основные пиры легли, найден резервный** - какие основные
  отвалились, какой резервный добавлен взамен (включая найденный
  через аварийный SOS-перебор)
- **Основные пиры снова живы** - какие резервные удалены
- **Пропадал интернет целиком** (не только Yggdrasil) - одно
  сообщение с обоими точными временами
- **Устройство недоступно / снова на связи** - с указанием, сколько
  было недоступно
- **Вход/выход из аварийного режима по батарее**
- **SOS-перебор начался / нашёл пира / завершился без результата**
- **Доступна новая версия на GitHub**

Рутинные проверки ("всё в порядке, без изменений") в Telegram **не**
шлются - только реальные события, чтобы не спамить.

### Настройка (один раз)

1. Открой `@BotFather` в Telegram, отправь `/newbot`, следуй
   инструкциям - получишь токен вида `123456:ABC-DEF...`
2. Напиши что-нибудь своему новому боту (любое сообщение)
3. Открой в браузере:
   `https://api.telegram.org/bot<ТВОЙ_ТОКЕН>/getUpdates`
4. В ответе найди число в поле `"chat":{"id": ЭТО_ЧИСЛО}`
5. Переименуй `notify.conf.example` в `notify.conf` (та же папка, что
   `ygg_watchdog.exe`), впиши токен и chat_id:
   ```
   BOT_TOKEN=123456:ABC-DEF...
   CHAT_ID=987654321
   ```

Если файла `notify.conf` нет вообще, или в нём не хватает одного из
полей - уведомления просто молча выключены, ничего не ломается и не
падает с ошибкой.

**Если у тебя два устройства (например Windows-ноутбук и Linux-сервер
Kjele) шлют уведомления в одного и того же бота** - в каждом сообщении
автоматически указывается имя устройства-отправителя (реальное имя
компьютера), чтобы не путать, откуда пришло.

## Логи

Файл `watchdog.log` рядом с `.exe`. По умолчанию видны только
осмысленные события (что произошло на каждой проверке, не только
аномалии). Для подробностей:
```
ygg_watchdog.exe -v tick
```
Логи старше 14 дней подчищаются автоматически.

## Проверка, что служба Yggdrasil тоже настроена на автозапуск

Это отдельная от watchdog служба - ставит её сам установщик Yggdrasil:
```
sc qc Yggdrasil
```
Ищи `START_TYPE: 2 AUTO_START`.

## Известные технические детали (на случай если пригодится позже)

- Задача Планировщика зарегистрирована от `SYSTEM` - специально, чтобы
  не зависеть от входа в систему и не показывать окно на рабочем столе
  (сессия 0)
- Файл состояния (`state.txt`) - простой текстовый формат `ключ=значение`,
  не JSON - читается построчно, при парсинге аккуратно обрезается
  завершающий `\r`
- `AdminListen` в `yggdrasil.conf` должен быть на отдельном порту
  (`tcp://127.0.0.1:9002`), не на дефолтном 9001 - иначе `yggdrasilctl`
  может случайно достучаться не туда при резолвинге `localhost` в IPv6
- SHA-256 для одобрения VPN-скрипта считается через встроенный в
  Windows `bcrypt.lib` (Cryptography API: Next Generation) - не нужна
  никакая внешняя библиотека
- Обновление себя же (`apply-update`) не может напрямую заменить
  работающий `.exe` (файл заблокирован ОС) - поэтому используется
  короткоживущий `.cmd`-скрипт, который ждёт завершения процесса и
  переименовывает файлы уже после выхода

## Команда напрямую (без меню)

```
ygg_watchdog.exe tick
ygg_watchdog.exe install-task
ygg_watchdog.exe uninstall-task
ygg_watchdog.exe add-region <номер_или_slug> <номер_или_город>
ygg_watchdog.exe remove-region
ygg_watchdog.exe list-countries
ygg_watchdog.exe list-cities <страна>
ygg_watchdog.exe list-main-peers
ygg_watchdog.exe add-main-peer tls://host:port
ygg_watchdog.exe remove-main-peer 2
ygg_watchdog.exe set-home-region russia Moscow  # город необязателен; без аргумента или "clear" - снять
ygg_watchdog.exe list-devices
ygg_watchdog.exe add-device ThinkPad 200:1234:abcd::1
ygg_watchdog.exe remove-device ThinkPad
ygg_watchdog.exe approve-vpn-command C:\Tools\vpn-restart.bat
ygg_watchdog.exe clear-vpn-command
ygg_watchdog.exe check-update
ygg_watchdog.exe apply-update
ygg_watchdog.exe restart-yggdrasil
ygg_watchdog.exe restart-yggdrasil-delayed 15
```
