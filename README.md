<h1 align="center">ygg-watchdog</h1>

Программа для [Yggdrasil](https://yggdrasil-network.github.io/): следит за связью, сама восстанавливает её, когда что-то идёт не так, и сообщает о сбоях в Telegram. Есть версии для Windows (C++, окно, значок в трее, Планировщик заданий) и Linux (C++, полноэкранное окно в терминале, systemd-таймер). Логика проверок у них одна.

## Быстрый старт

- **Windows:** скачай из папки [`windows`](windows) файлы `ygg_watchdog.exe`, `ygg_guard.exe`, `cities.dat` и `notify.conf.example` и положи их в одну папку. Дважды кликни `ygg_watchdog.exe` и в окне на вкладке «Управление» нажми «Установить».
- **Linux:** выполни команды из раздела [Установка → Linux](#linux), программа встанет в `~/ygg-watchdog`.

## Что делает

Описание общее для обеих версий; где они различаются — сказано отдельно.

Каждые 3 минуты программа проверяет связь и действует сама:

- **Держит от 3 до 7 живых пиров.** Основные пиры (из `yggdrasil.conf`) она не трогает никогда. Если живых меньше трёх, добирает резервные в той же проверке. Если больше семи, убирает лишние резервные, начиная с самой большой задержки.
- **Пир «подключён», но постоянно рвётся.** Если пир переподключился 3 раза за полчаса, он не считается живым: формально он Up, но трафик через него не идёт. Ему ищется замена.
- **Где искать замену.** По очереди, без повторов одной страны:
  1. страна, откуда реально выходит трафик (по GeoIP, так учитывается VPN);
  2. регион поездки;
  3. домашний регион;
  4. страна основных пиров.

  Внутри страны первыми идут пиры, ближайшие к выбранному городу (по координатам из базы GeoNames), и те, что раньше работали надёжно. Сначала быстрая проба портов, потом настоящее рукопожатие только с теми, кто ответил.
- **Обычный поиск не помог и живых пиров нет совсем** — включается крайний перебор: все пиры всех стран из публичного списка. Перебор ограничен по времени одной проверки и продолжается в следующей с того же места. После полного прохода без результата — пауза 12 часов.
- **Служба Yggdrasil остановлена.** Если у неё тип запуска «Автоматически» (на Linux — `systemctl enable`), программа запускает её и сообщает. Если «Вручную» или «Отключена», считает, что её остановили намеренно: только сообщает.
- **Сломался `yggdrasil.conf`** (например, ошибка при ручной правке). Программа хранит рабочую копию конфига и предлагает вернуть её кнопкой в окне. Заменяет только после подтверждения, битый файл сохраняется рядом.
- **Сетевой адаптер Yggdrasil не создан, выключен или без маршрута 200::/7.** Пиры могут быть живы, а трафик всё равно не идёт. Программа это замечает и сообщает.
- **Пропал интернет целиком.** Программа не тратит время на поиск пиров, ждёт и потом присылает одно сообщение с точным временем пропажи и возврата.
- **Своё устройство недоступно.** Если связь в порядке, а добавленный вручную компьютер не отвечает, программа разбирает почему. Варианты: завис свой Yggdrasil; маршрут перехватил VPN-клиент; пакет режется прямо на этом компьютере; сеть не находит путь до устройства; устройство молчит само. Потом пробует то, что можно сделать отсюда: перезапустить свою службу, запустить одобренный VPN-скрипт, временно подключить общие с устройством пиры. В уведомлении — причина, что сделано и помогло ли.
- **Критический заряд батареи** (≤5%, не на зарядке) — все проверки на паузе до зарядки. Одно сообщение на вход и одно на выход.
- **Целостность самой программы (Windows).** Задача Планировщика запускает маленького стража `ygg_guard.exe`. Если `ygg_watchdog.exe` повреждён или пропал, страж скачивает целый файл из этого репозитория и сверяет его отпечаток. Сторож, в свою очередь, следит за стражем.
- **Автопроверки замолчали (Windows)** (задачу удалили или выключили) — значок в трее присылает сообщение в Telegram и на экран и предлагает восстановить задачу. Восстанавливает только после подтверждения.
- **Статистика.** Для каждого пира копятся доступность, средняя задержка, P95 и разброс за 1 час, сутки и неделю, а также надёжность за 30 суток. Её видно на вкладке «Статистика», можно выгрузить в CSV.
- **Фаервол и антивирус** программа не трогает. Перед крайним перебором она только читает правила фаервола и предупреждает, если похоже на блокировку.
- **VPN.** По умолчанию программа в VPN-клиент не лезет. Можно один раз одобрить свой скрипт перезапуска VPN. Перед каждым запуском программа сверяет его SHA-256 и отказывается запускать, если скрипт изменился хоть на байт.
- **Обновления.** Раз в сутки программа сравнивает свою версию с версией в репозитории и только сообщает. Ставится обновление кнопкой в окне.

Для ручного управления на Windows есть окно с вкладками: обзор, пиры, каталог публичных пиров, статистика, регион, устройства, журнал, управление. Всё доступно и с клавиатуры (Tab, стрелки, Enter). Есть также значок в трее со своими всплывающими окнами.

На Linux то же самое — полноэкранное окно прямо в терминале (команда `ygg-watchdog`): те же экраны, переход цифрами 1–0, стрелки, Enter и Esc. Значка в трее и стража там нет: проверки запускает systemd-таймер, а целостность файла проверяется при обновлении.

**Уведомления в Telegram** (необязательно) — только о значимых событиях: связь пропала или вернулась, добавлены резервные, пропадал интернет, устройство недоступно или вернулось, служба или адаптер Yggdrasil, битый конфиг, крайний перебор, батарея, автопроверки замолчали, восстановлен exe, вышла новая версия. Рутинное «всё в порядке» не присылается. В каждом сообщении указано имя устройства.

## Установка

### Windows

**1. Скачай файлы.** Открой папку [`windows`](windows) в этом репозитории и скачай оттуда файлы. Чтобы скачать файл, кликни по нему, а потом на кнопку **Download raw file** (стрелка вниз справа над содержимым).

| Файл | Зачем |
|---|---|
| `ygg_watchdog.exe` | Сама программа: окно, проверки, значок в трее |
| `ygg_guard.exe` | Страж: его запускает Планировщик, он проверяет целостность программы |
| `cities.dat` | База городов, без неё не работает выбор города и сортировка по расстоянию |
| `notify.conf.example` | Пример настроек Telegram (нужен, только если хочешь уведомления) |

Остальные файлы в папке (`.cpp`, `.bat`, `.rc`, `.ico`, папки `gui` и `tests`) — исходники, сборка и тесты, для работы они не нужны.

**2. Положи их в одну постоянную папку**, например `C:\Tools\ygg-watchdog`. Не оставляй их в «Загрузках»: задача Планировщика запоминает путь к программе, и если потом переместить папку, проверки перестанут запускаться (значок в трее это заметит и предложит восстановить задачу).

**3. Дважды кликни `ygg_watchdog.exe`.** Windows попросит права администратора, соглашайся. Откроется окно.

**4. Вкладка «Управление» [N] → «Установить».** Это создаст задачу в Планировщике Windows. Программа будет проверять связь каждые 3 минуты в фоне, даже когда никто не вошёл в систему, и сразу после пробуждения. Больше ничего делать не нужно.

Если программу блокирует Защитник Windows, добавь папку программы в исключения (Безопасность Windows → Защита от вирусов и угроз → Управление настройками → Исключения).

**Собрать самому** (если поменял код): скачай весь репозиторий (зелёная кнопка **Code → Download ZIP**), открой папку `windows` и запусти `run_ygg_watchdog.bat`. Он соберёт `ygg_watchdog.exe` и `ygg_guard.exe`. Нужен компилятор: [MinGW-w64](https://winlibs.com/) или Visual Studio с компонентом «Разработка классических приложений на C++». Тесты: `tests\run_tests.bat`.

Подробно про окно, файлы и команды: [windows/README_WINDOWS.md](windows/README_WINDOWS.md)

### Linux

Нужны systemd, git и установленный Yggdrasil; для сборки — `g++` и `libssl-dev`.

**Установка** — скопируй и выполни целиком:

```bash
sudo apt install g++ libssl-dev git
git clone --depth 1 --filter=blob:none --sparse https://github.com/Yozmor/ygg-watchdog.git /tmp/ygg-src
git -C /tmp/ygg-src sparse-checkout set linux
mkdir -p ~/ygg-watchdog
cp -r /tmp/ygg-src/linux/. ~/ygg-watchdog/
rm -rf /tmp/ygg-src
cd ~/ygg-watchdog
chmod +x build.sh install.sh tests/run_tests.sh ygg-watchdog 2>/dev/null   # разрешить запуск 
./build.sh
sudo ./install.sh
```

Что происходит по шагам:
1. ставятся компилятор и OpenSSL для сборки;
2. во временную папку `/tmp/ygg-src` скачивается только папка `linux` из репозитория (Windows-часть не загружается);
3. создаётся папка программы `~/ygg-watchdog`, туда копируются файлы из папки `linux` (именно файлы, без лишней вложенной папки);
4. временная папка удаляется;
5. `chmod +x` разрешает запуск скриптов и программы: при коммите с Windows это разрешение теряется;
6. `build.sh` собирает программу `ygg-watchdog` (шаг можно пропустить — готовая уже лежит в репозитории);
7. `install.sh` проверяет программу, включает systemd-таймер (каждые 3 минуты и после пробуждения) и добавляет команду `ygg-watchdog`.

Программа живёт и работает в `~/ygg-watchdog`. Не клонируй репозиторий прямо в `~/ygg-watchdog`: там должна лежать сама программа, а не весь репозиторий.

**Переход с прежней Python-версии** — те же команды в ту же папку. Старые `.py`-файлы и юниты `ygg-watchdog-tick.*` уберутся сами, а резервные пиры, регионы и устройства из `state.json` перенесутся при первом запуске.

**Проверка и работа:**

```bash
ygg-watchdog                                    # окно
ygg-watchdog --selftest                         # печатает версию, если программа цела
tail -f ~/ygg-watchdog/watchdog.log             # лог
```

**Удаление:**

```bash
cd ~/ygg-watchdog && sudo ./install.sh --remove   # выключить автопроверку
sudo rm -rf ~/ygg-watchdog                        # удалить файлы
```

Подробно: [linux/README_LINUX.md](linux/README_LINUX.md)

## Регионы поиска

Программе нужно знать, где искать замену пирам. Она идёт по очереди и не проверяет одну страну дважды:

1. **Выход трафика** — страна, которую видит интернет: программа смотрит свой публичный IP через GeoIP. Если трафик идёт через VPN, это страна VPN. Значение кэшируется на час.
2. **Регион поездки** — страна и город, заданные вручную на время поездки. Основные пиры при этом работают как обычно, регион влияет только на поиск замены.
3. **Домашний регион** — постоянный запасной вариант, задаётся вручную.
4. **Страна основных пиров** — если ничего из перечисленного не задано и GeoIP недоступен.

Если задан город, первыми проверяются пиры, ближайшие к нему.

На Windows всё это задаётся на вкладке «Регион» окна или командами `add-region <страна> [город]`, `remove-region`, `set-home-region <страна> [город]`. На Linux — экран **6** окна или те же команды:

```bash
ygg-watchdog list-countries
sudo ygg-watchdog set-region Россия Владивосток
sudo ygg-watchdog set-home-region russia Moscow
```

## Мониторинг устройств

Можно добавить несколько своих компьютеров (телефон намеренно не поддерживается) для проверки доступности внутри сети Yggdrasil. Проверяются они только после того, как связь через пиры подтверждена: если её нет, проверять устройства бессмысленно. На Windows все устройства проверяются одновременно. Если пинг закрыт, проверяются порты 445, 3389 и 22.

На Windows у недоступного устройства разбирается причина по шагам: свой Yggdrasil → маршрут через адаптер Yggdrasil → не режется ли пакет на этом компьютере → находит ли сеть путь → отвечает ли само устройство. Если недоступность подтвердилась, программа пробует починить то, что можно со своей стороны, не чаще раза в час. Устройству можно задать **общие пиры** — те, к которым подключено и оно само. Если сеть не находит путь, программа подключит их на время и уберёт, когда устройство вернётся. Причину на стороне самого устройства с другого компьютера не узнать: для этого программа должна стоять и на нём.

На Windows — вкладка «Устройства» (кнопка «Диагностика» разбирает прямо сейчас), на Linux — экран **7** окна. На обеих работают команды `add-device` / `diagnose-device` / `list-devices` / `remove-device`:

```bash
sudo ygg-watchdog add-device ThinkPad 200:1234:abcd::1
sudo ygg-watchdog diagnose-device ThinkPad
sudo ygg-watchdog remove-device ThinkPad
```

## VPN (продвинутый режим)

По умолчанию программа ничего в VPN не настраивает, а только предупреждает, если похоже, что проблема в нём. Если хочешь, чтобы она сама перезапускала VPN при сбое, один раз одобри свой скрипт перезапуска:

```bash
# Linux
sudo ygg-watchdog approve-vpn-command /путь/к/своему/restart-vpn.sh
```

На Windows — «Управление» → «Выбрать скрипт…», на Linux — экран **0** окна (или команда `approve-vpn-command <путь>`).

Перед каждым запуском скрипта программа пересчитывает его SHA-256 и сравнивает с тем, что был при одобрении. Если скрипт изменился хоть на байт, запуск откажется, пока его не одобрят снова. Снять одобрение: `clear-vpn-command`.

## Обновления

Релизов нет: всё лежит прямо в репозитории.

- **Windows.** Раз в сутки программа читает `CURRENT_VERSION` в `windows/ygg_watchdog.cpp` на GitHub. Если версия там новее, присылает уведомление и сама ничего не ставит. Обновление ставится кнопкой «Управление» → «Установить» (или командой `apply-update`). Дальше программа:
  1. скачивает `windows/ygg_watchdog.exe` и сверяет его git-отпечаток с репозиторием;
  2. запускает новую версию в режиме самопроверки: она должна запуститься и назвать ту версию, что указана в исходнике;
  3. сразу ставит новый файл на место, а старый сохраняет как `ygg_watchdog.exe.backup`. Ничего закрывать не нужно: значок в трее перезапускается сам, а окно достаточно закрыть и открыть заново;
  4. если новая версия на месте не прошла самопроверку, старая возвращается сама, и приходит уведомление;
  5. сверяет стража `ygg_guard.exe` с репозиторием: если его нет, он битый или другой — скачивает целый. Сторож и так на каждой проверке следит, на месте ли страж, и сам возвращает задачу на него.
- **Linux.** Так же, но версия берётся из `WATCHDOG_VERSION` в `linux/src/watchdog/version.h`, а файл — `linux/ygg-watchdog`. Ставится кнопкой «Управление» → **[i]** в окне или командой `sudo ygg-watchdog apply-update`: скачать, сверить отпечаток, самопроверка, замена (старый — `ygg-watchdog.backup`), откат, если новая не запустилась.

### Выпуск новой версии (для автора)

- **Windows:** подними `CURRENT_VERSION` в `windows/ygg_watchdog.cpp`, собери `run_ygg_watchdog.bat` и закоммить вместе `ygg_watchdog.cpp`, `ygg_watchdog.exe` и `ygg_guard.exe`.
- **Linux:** подними `WATCHDOG_VERSION` в `linux/src/watchdog/version.h`, собери `./build.sh` и закоммить вместе `version.h` и `linux/ygg-watchdog`.

Если номер версии подняли, а программу забыли, сторож это заметит и откажется ставить старый файл как новый.

## Уведомления в Telegram

1. Создай бота через `@BotFather` (`/newbot`) и получи токен.
2. Напиши своему боту любое сообщение.
3. Открой `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найди число в `"chat":{"id": ...}`.
4. Переименуй `notify.conf.example` в `notify.conf` и впиши:

```
BOT_TOKEN=123456:ABC-DEF...
CHAT_ID=987654321
```

На Windows то же самое можно сделать в окне: «Управление» → поля Telegram → «Сохранить», потом «Проверить». На Linux — экран **0** → **[n]**, потом **[m]** (файл получит права только для root).

**Как сообщения доходят до Telegram (Windows).** Прокси прописывать не нужно: программа сама перебирает пути, пока какой-то не сработает. Сработавший путь она запоминает. Порядок такой:

1. путь, который сработал в прошлый раз;
2. `PROXY=` из `notify.conf`, если задан;
3. подсказка от VPN-клиента (см. ниже);
4. напрямую — работает, когда VPN-клиент в TUN-режиме;
5. системный прокси пользователя;
6. автопоиск: какие известные VPN-клиенты (Karing, sing-box, v2rayN/v2rayTun, xray, NekoBox, Hiddify, Clash/mihomo, naive и другие) слушают порты на `127.0.0.1`. Каждый такой порт проверяется запросом к Telegram.

Тот же порядок работает и для GitHub (база пиров, обновления). На вкладке «Управление» видно, когда и каким путём ушло последнее сообщение, а если не ушло, то почему.

Свой VPN-клиент можно подключить двумя способами:
- добавить часть имени его exe в `notify.conf`: `PROXY_CLIENTS=myclient, другой`;
- научить клиент самому сообщать порт: при запуске он пишет адрес локального HTTP-прокси (например `127.0.0.1:2080`) в значение `LocalProxy` ключа реестра `HKLM\SOFTWARE\Yozmor` или первой строкой в файл `%ProgramData%\Yozmor\local_proxy.txt`, а при выходе удаляет.

Ограничение Windows: прокси должен понимать HTTP `CONNECT` (порт типа `http` или `mixed`), чистый SOCKS не подойдёт. В TUN-режиме прокси не нужен вовсе.

**На Linux** порядок тот же, только вместо системного прокси — `https_proxy` из окружения, подсказка VPN-клиента — файл `/run/yozmor/local_proxy.txt` (или `/etc/yozmor/local_proxy.txt`), а прокси может быть и HTTP, и SOCKS5 (`socks5://127.0.0.1:10808`).

Канал односторонний: программа только отправляет сообщения и команд из Telegram не принимает. Без `notify.conf` уведомления просто выключены, всё остальное работает.

## Команды без меню (Linux)

```bash
sudo ygg-watchdog tick                          # одна проверка (-v - подробно)
sudo ygg-watchdog status                        # статус
sudo ygg-watchdog diagnose                      # почему нет связи
ygg-watchdog list-countries                     # список стран
ygg-watchdog list-cities russia                 # города страны
sudo ygg-watchdog set-region russia Vladivostok # регион поездки
sudo ygg-watchdog remove-region                 # снять регион
sudo ygg-watchdog set-home-region russia        # домашний регион
sudo ygg-watchdog add-main-peer tls://host:port # добавить основной пир
sudo ygg-watchdog verify-peer tls://host:port   # проверить пир рукопожатием
sudo ygg-watchdog add-device ThinkPad 200::1    # устройство для мониторинга
sudo ygg-watchdog approve-vpn-command ./vpn.sh  # одобрить VPN-скрипт
sudo ygg-watchdog restart-yggdrasil-delayed 15  # перезапуск через 15 с
sudo ygg-watchdog check-update | apply-update   # обновление
ygg-watchdog help                               # все команды
```

Подробно — в [linux/README_LINUX.md](linux/README_LINUX.md). Команды Windows-версии — в [windows/README_WINDOWS.md](windows/README_WINDOWS.md#команды-для-планировщика-окна-и-консоли).
