<h1 align="center">ygg-watchdog</h1>

Программа для [Yggdrasil](https://yggdrasil-network.github.io/), которая следит за связью и сама её восстанавливает, когда что-то идёт не так, а о сбоях сообщает в Telegram. Есть версии для Linux (Python + systemd) и Windows (C++ + Планировщик заданий).

## Быстрый старт

- **Windows:** скачай из папки [`windows`](windows) файлы — `ygg_watchdog.exe`, `cities.dat`, `notify.conf.example` — положи их в одну папку, дважды кликни `ygg_watchdog.exe` и в меню нажми **2**.
- **Linux:** выполни 6 команд из раздела [Установка → Linux](#linux), программа встанет в `~/ygg-watchdog`.

## Что делает

Каждые 3 минуты программа проверяет связь и действует сама, по нарастающей:

- **Все основные пиры легли** — ищет замену: сначала в регионе, откуда реально идёт исходящий трафик (egress-регион, определяется по IP через GeoIP — так корректно учитывается VPN, если он держит маршрут по умолчанию), иначе — в домашнем регионе, который можно задать вручную как постоянный fallback. Кандидата проверяет настоящим рукопожатием и добавляет рабочего как резервного.
- **Обычный поиск не помог** — крайняя мера: аварийный (SOS) перебор ВСЕХ пиров по ВСЕМ странам из публичного списка. Перебор ограничен по времени за один тик (не по числу пиров), возобновляемый — следующая проверка продолжает ровно с того места, где предыдущая остановилась. После полного прохода без результата — 12 часов паузы, чтобы не долбить сеть без толку.
- **Основной пир снова жив** — резервные убираются.
- **Пропал интернет целиком** — не тратит время на бесполезный поиск пиров, ждёт восстановления и записывает в лог, когда связь пропала и когда вернулась.
- **Региональный режим** — можно выбрать страну и город вручную, и программа будет держать пиры, ближайшие к этому городу (по реальным координатам из базы GeoNames).
- **Устройство недоступно** — если связь в порядке, а конкретное добавленное вручную устройство не отвечает, программа проверяет, перегружен ли Yggdrasil на этой машине, и если да — перезапускает его. О восстановлении связи с устройством сообщает с указанием, сколько оно было недоступно.
- **Критический заряд батареи** (≤5%, не на зарядке) — на время входит в аварийный режим и отключает вообще все проверки, одно уведомление. Выходит из него сам, как только заряд пошёл в плюс или началась зарядка.
- **Фаервол/антивирус** — программе НЕ дан доступ менять фаервол: она его не трогает и не настраивает. Но перед самым долгим и дорогим способом — крайним перебором (последняя надежда, когда обычный поиск пира не сработал) — она сама читает текущие правила фаервола (только чтение) и, если похоже на блокировку исходящих соединений, сразу пишет об этом в лог и Telegram, не дожидаясь результата перебора. Если дело в антивирусе (например, он блокирует неподписанный exe) — это не видно через правила фаервола, тут поможет только вручную добавленное исключение для `ygg_watchdog.exe`/`watchdog_daemon.py`.
- **VPN** — базовый уровень (по умолчанию) в сам VPN-клиент не лезет вообще, только предупреждает, если похоже, что проблема в нём. Продвинутый уровень — свой скрипт перезапуска VPN, который нужно одобрить один раз руками; одобрение защищено проверкой содержимого скрипта (SHA-256) перед каждым запуском — если скрипт с тех пор изменился хоть на байт, запуск отказывается.
- **Обновления** — раз в сутки молча проверяет на GitHub, нет ли новой версии, и если есть — только уведомляет. Ничего не скачивает и не меняет сама; обновление ставится отдельной явной командой.

Для ручного управления есть меню: статус, основные пиры, домашний/региональный режим, устройства для мониторинга, VPN-скрипт, проверка обновлений, перезапуск Yggdrasil (в том числе с задержкой, чтобы не оборвать свою же сессию, если подключён через Yggdrasil).

**Уведомления в Telegram** (необязательно): бот присылает сообщение о значимых событиях — пиры легли/нашлась замена/вернулись, пропадал интернет, устройство недоступно/восстановилось, аварийный SOS-перебор начался/нашёл пира/не нашёл, вошли или вышли из аварийного режима по батарее. Рутинные проверки «всё в порядке» не присылаются. Если несколько устройств шлют уведомления одному боту, в каждом сообщении указано имя устройства.

## Установка

### Windows

**1. Скачай файлы.** Открой папку [`windows`](windows) в этом репозитории и скачай оттуда файлы. Чтобы скачать файл, кликни по нему, а потом на кнопку **Download raw file** (стрелка вниз справа над содержимым).

| Файл | Зачем |
|---|---|
| `ygg_watchdog.exe` | Сама программа |
| `cities.dat` | База городов, без неё не работает выбор региона |
| `notify.conf.example` | Пример настроек Telegram (нужен, только если хочешь уведомления) |

Остальные файлы в папке (`.cpp`, `.bat`, `.rc`, `.ico`) — исходники и сборка, для работы они не нужны.

**2. Положи их в одну постоянную папку**, например `C:\Tools\ygg-watchdog`. Не оставляй в «Загрузках»: задача планировщика запоминает путь к программе, и если потом переместить папку, проверки перестанут запускаться.

**3. Дважды кликни `ygg_watchdog.exe`.** Windows попросит права администратора, соглашайся. Откроется меню.

**4. Нажми `2` и Enter.** Это установит задачу в Планировщик Windows: программа будет проверять связь каждые 3 минуты в фоне, даже когда никто не вошёл в систему. Больше ничего делать не нужно.

Если программу (или антивирус) блокирует Защитник Windows — добавь папку программы в исключения Защитника (Безопасность Windows → Защита от вирусов и угроз → Управление настройками → Исключения).

**Собрать exe самому** (если поменял код): скачай весь репозиторий (зелёная кнопка **Code → Download ZIP**), открой папку `windows` и запусти `run_ygg_watchdog.bat` — он соберёт `ygg_watchdog.exe` с иконкой. Нужен компилятор: [MinGW-w64](https://winlibs.com/) или Visual Studio с компонентом «Разработка классических приложений на C++».

Подробно про меню и настройки: [windows/README_WINDOWS.md](windows/README_WINDOWS.md)

### Linux

Нужны Python 3, systemd, git и установленный Yggdrasil.

**Установка** — скопируй и выполни целиком:

```bash
git clone https://github.com/Yozmor/ygg-watchdog.git /tmp/ygg-src
mkdir -p ~/ygg-watchdog
cp -r /tmp/ygg-src/linux/. ~/ygg-watchdog/
rm -rf /tmp/ygg-src
cd ~/ygg-watchdog
sudo ./install.sh
```

Что происходит по шагам:
1. репозиторий скачивается во временную папку `/tmp/ygg-src`;
2. создаётся папка программы `~/ygg-watchdog`;
3. туда копируются файлы из папки `linux` (именно файлы, без лишней вложенной папки);
4. временная папка удаляется;
5. `install.sh` включает автопроверку каждые 3 минуты и добавляет команду `ygg-watchdog` для меню.

Программа живёт и работает в `~/ygg-watchdog`. Не клонируй репозиторий прямо в `~/ygg-watchdog`: там должна лежать сама программа, а не весь репозиторий.

**Обновление** — те же команды. Новые файлы заменят старые, а твои `notify.conf`, `state.json` и логи останутся: в репозитории их нет, поэтому они не перезаписываются. Либо, после первой установки, можно обновляться прямо из меню/команды `apply-update` — см. ниже.

**Проверка и работа:**

```bash
ygg-watchdog                                    # меню
sudo python3 -B ~/ygg-watchdog/selftest.py      # самопроверка, все пункты должны быть OK
tail -f ~/ygg-watchdog/watchdog.log             # лог
```

**Удаление:**

```bash
cd ~/ygg-watchdog && sudo ./install.sh --remove   # выключить автопроверку
sudo rm -rf ~/ygg-watchdog                        # удалить файлы
```

Подробно: [linux/README_LINUX.md](linux/README_LINUX.md)

## Домашний и egress-регион

Для поиска резервных пиров программе нужно знать, в каком регионе их искать. Раньше это определялось по стране самих основных пиров — неверно, потому что реальный исходящий трафик идёт через тот интерфейс, который сейчас держит маршрут по умолчанию (обычный или VPN), а не через какой-то конкретный пир. Теперь порядок такой:

1. **Egress-регион** — определяется автоматически: программа смотрит свой публичный IP и переводит его в страну через GeoIP. Кэшируется на час, чтобы не дёргать сервисы GeoIP каждые 3 минуты.
2. **Домашний регион** — если GeoIP недоступен (нет сети наружу, сервисы легли), используется регион, заданный вручную один раз через меню/команду `set-home-region`. Это постоянный fallback, не связанный с тем, где физически находится пир.

Задать домашний регион:

```bash
# Linux
sudo python3 watchdog_daemon.py list-countries
sudo python3 watchdog_daemon.py set-home-region russia
```

На Windows — пункты меню «Список стран» и «Задать домашний регион», либо команды `list-countries` / `set-home-region <страна>`.

## Мониторинг устройств

Можно вручную добавить до нескольких устройств (ноутбуков — телефон намеренно не поддерживается) для проверки доступности внутри сети Yggdrasil. Проверяются они только ПОСЛЕ того, как основная связность уже подтверждена живой — если самого Yggdrasil-соединения нет, отдельно проверять устройства бессмысленно.

```bash
# Linux
sudo python3 watchdog_daemon.py add-device ThinkPad 200:1234:abcd::1
sudo python3 watchdog_daemon.py list-devices
sudo python3 watchdog_daemon.py remove-device ThinkPad
```

На Windows — те же действия через пункты меню или команды `add-device`/`list-devices`/`remove-device`.

## VPN (продвинутый режим)

Базовый режим ничего не настраивает — он просто предупреждает, если похоже, что проблема в VPN. Если хочешь, чтобы программа сама перезапускала VPN при сбое, нужно один раз одобрить свой собственный скрипт перезапуска:

```bash
# Linux
sudo python3 watchdog_daemon.py approve-vpn-command /путь/к/своему/restart-vpn.sh
```

На Windows — пункт меню «Одобрить VPN-скрипт» (или команда `approve-vpn-command <путь>`).

После одобрения перед КАЖДЫМ запуском скрипта программа пересчитывает его SHA-256 и сравнивает с тем, что был на момент одобрения. Если скрипт с тех пор изменился хоть на байт — запуск откажется, пока его не одобрят снова. Снять одобрение: `clear-vpn-command`.

## Обновления

Раз в сутки программа тихо проверяет последний релиз на GitHub. Если версия новее — присылает уведомление и пишет в лог, но сама НИЧЕГО не скачивает. Чтобы обновиться:

```bash
# Linux
sudo python3 watchdog_daemon.py check-update   # посмотреть, есть ли новая версия
sudo python3 watchdog_daemon.py apply-update    # скачать и поставить (с автоматическим откатом при сбое)
```

На Windows — те же команды/пункты меню; сборка `.exe`, если новая версия не содержит готового файла, собирается самостоятельно из исходников релиза (ссылка даётся в сообщении).

## Уведомления в Telegram

1. Создай бота через `@BotFather` (`/newbot`) и получи токен.
2. Напиши своему боту любое сообщение.
3. Открой `https://api.telegram.org/bot<ТОКЕН>/getUpdates` и найди число в `"chat":{"id": ...}`.
4. Переименуй `notify.conf.example` в `notify.conf` и впиши:

```
BOT_TOKEN=123456:ABC-DEF...
CHAT_ID=987654321
```

На Windows, если Telegram у тебя открывается только через локальный прокси, впиши его в `PROXY=адрес:порт` в том же файле.

Без `notify.conf` уведомления просто выключены, всё остальное работает.

## Команды без меню (Linux)

```bash
cd ~/ygg-watchdog
sudo python3 watchdog_daemon.py tick                          # одна проверка
sudo python3 watchdog_daemon.py status                        # статус
sudo python3 watchdog_daemon.py list-countries                # список стран
sudo python3 watchdog_daemon.py list-cities russia            # города страны
sudo python3 watchdog_daemon.py add-region russia Vladivostok # включить регион
sudo python3 watchdog_daemon.py remove-region                 # выключить регион
sudo python3 watchdog_daemon.py set-home-region russia        # домашний регион
sudo python3 watchdog_daemon.py add-main-peer tls://host:port # добавить основной пир
sudo python3 watchdog_daemon.py add-device ThinkPad 200::1    # устройство для мониторинга
sudo python3 watchdog_daemon.py approve-vpn-command ./vpn.sh  # одобрить VPN-скрипт
sudo python3 watchdog_daemon.py check-update                 # проверить обновления
sudo python3 watchdog_daemon.py apply-update                 # поставить обновление
sudo python3 watchdog_daemon.py restart-yggdrasil-delayed 15  # перезапуск через 15 с
```
