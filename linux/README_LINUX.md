# ygg-watchdog для Linux

Сторож пиров Yggdrasil: раз в 3 минуты проверяет связь и сам её чинит. Одна программа на C++ без сторонних библиотек (только OpenSSL, который есть в любой Ubuntu). Ручное управление — полноэкранное окно прямо в терминале: команда `ygg-watchdog`.

Общее описание и Windows-версия — в [README.md](../README.md).

## Что работает автоматически

Раз в 3 минуты systemd-таймер запускает проверку (`ygg-watchdog tick`). Пропущенная во сне проверка выполняется сразу после пробуждения.

- **Живых пиров держится 3–7.** Меньше трёх — сторож добирает резервные, больше семи — лишние резервные (с самой большой задержкой) убирает. Основные пиры из `yggdrasil.conf` он не трогает никогда.
- **Где искать замену**, по очереди: страна выхода трафика (GeoIP) → регион поездки → домашний регион → страна основных пиров. В каждой стране — быстрая проба портов всех кандидатов, потом настоящее рукопожатие через сам Yggdrasil только с отвечающими. Кандидаты ближе к выбранному городу и с хорошей историей проверяются первыми.
- **Рвущиеся пиры.** Пир, который «Up», но переподключается 3 раза за полчаса, живым не считается.
- **Нет интернета** — замену не ищет, ждёт; когда сеть вернётся, пришлёт одно сообщение с обоими временами. Если сырые IP отвечают, а имена не находятся, сам сбрасывает зависший кэш DNS (`resolvectl flush-caches`).
- **Крайний перебор.** Обычный поиск не помог — перебирает пиры всех стран, понемногу за каждую проверку, с курсором; после полного прохода без результата — пауза 12 часов.
- **Служба Yggdrasil.** Остановилась, а автозапуск включён — запускает. Автозапуск выключен — значит, остановили намеренно: только сообщает.
- **Конфиг.** Держит рядом рабочую копию `yggdrasil.conf.good`. Если конфиг перестал читаться — сообщает и предлагает вернуть копию (заменяет только после подтверждения).
- **Адаптер Yggdrasil.** Пиры живы, но у интерфейса нет адреса, он выключен или нет маршрута `200::/7` — сообщает.
- **Устройства.** Свои компьютеры по адресу Yggdrasil; если какое-то не отвечает — разбирает по шагам почему (Yggdrasil тут, маршрут, свой фаервол, путь в сети) и делает то, что можно сделать отсюда: перезапуск службы, временное подключение общих пиров.
- **VPN.** Сам VPN не трогает. Если GitHub не открывается, а на машине работает xray/v2ray/sing-box — проверяет, отвечает ли сервер VPN через локальный socks, и сообщает. Свой скрипт перезапуска VPN можно одобрить (привязка к SHA-256 файла).
- **Фаервол** — только читает правила ufw / iptables / ip6tables / nftables и подсказывает, если исходящие запрещены.
- **Батарея** (ноутбуки): заряд ≤ 5% без зарядки — все проверки на паузе до зарядки.
- **Обновления** — раз в сутки смотрит репозиторий и только сообщает; ставит по кнопке.

## Установка

Нужны установленный Yggdrasil и, для сборки, `g++` и `libssl-dev`:

```bash
sudo apt install g++ libssl-dev git
git clone --depth 1 --filter=blob:none --sparse https://github.com/Yozmor/ygg-watchdog.git /tmp/ygg-src
git -C /tmp/ygg-src sparse-checkout set linux
mkdir -p ~/ygg-watchdog
cp -r /tmp/ygg-src/linux/. ~/ygg-watchdog/
rm -rf /tmp/ygg-src
cd ~/ygg-watchdog
chmod +x build.sh install.sh tests/run_tests.sh ygg-watchdog 2>/dev/null   # разрешить запуск 
./build.sh              # можно пропустить: готовая ygg-watchdog уже лежит в папке
sudo ./install.sh
```

`install.sh` включает systemd-таймер (каждые 3 минуты и после пробуждения) и команду `ygg-watchdog`. Программа живёт и работает в `~/ygg-watchdog`: там её состояние, логи и настройки.

**Переход с Python-версии** — те же команды в ту же папку `~/ygg-watchdog`. Старые юниты `ygg-watchdog-tick.*` и файлы `.py` уберутся сами, а состояние (`state.json`: резервные пиры, регионы, устройства) перенесётся при первом запуске.

**Удаление:** `sudo ./install.sh --remove` (выключает таймер и команду, файлы остаются).

## Окно

```bash
ygg-watchdog
```

Попросит пароль sudo (нужен для yggdrasilctl, конфига и systemd).

| Клавиша | Экран |
|---|---|
| **1** | проверить сейчас |
| **2** | пиры: роль, задержка, время на связи; добавить/убрать основной, проверить пир рукопожатием |
| **3** | статистика: надёжность каждого пира, график задержки, полоса «на связи / нет», период 6 / 24 / 48 ч, выгрузка в CSV |
| **4** | почему нет связи: разбор ошибок основных пиров и что делать |
| **5** | каталог публичных пиров: страна с поиском по буквам, проба портов, проверка, добавление в основные |
| **6** | регион поездки и домашний: страна и город с поиском, расстояние до ближайшего пира |
| **7** | устройства: состояние, разбор по шагам, общие пиры |
| **8** | журнал событий (то же, что уходит в Telegram) |
| **9** | служба Yggdrasil: перезапуск сразу или через 15 с, остановка, автозапуск, лог, новая версия Yggdrasil |
| **0** | управление: таймер, обновления, Telegram, VPN-скрипт, рабочая копия конфига |

Везде: **↑ ↓** — выбор, **Enter** — открыть, **Esc** — назад, **t** — проверить сейчас, **q** — выход. В списках стран и городов можно сразу печатать — по-русски или латиницей.

## Обновления

Релизов нет: всё лежит в репозитории. Раз в сутки сторож читает `WATCHDOG_VERSION` в `linux/src/watchdog/version.h` на GitHub и, если там новее, сообщает. Установка — «Управление» → **[i]** (или `sudo ygg-watchdog apply-update`):

1. скачивается `linux/ygg-watchdog` и сверяется его git-отпечаток с репозиторием;
2. новая версия запускается с `--selftest` и должна назвать ту версию, что в исходнике (так ловится и «exe забыли закоммитить»);
3. файл заменяется, старый остаётся как `ygg-watchdog.backup`; если на месте новая версия не прошла самопроверку — старая возвращается сама.

## Уведомления в Telegram

«Управление» → **[n]**: токен от @BotFather и chat_id (из `https://api.telegram.org/bot<ТОКЕН>/getUpdates`). Сохраняется в `notify.conf` с правами только для root. **[m]** — тестовое сообщение.

Прокси прописывать не нужно — сторож перебирает пути, пока какой-то не сработает, и запоминает сработавший: прошлый удачный → `PROXY=` из `notify.conf` → подсказка VPN-клиента → напрямую → прокси из окружения (`https_proxy`) → автопоиск: какие известные VPN-клиенты (xray, v2ray, sing-box, Karing, NekoBox, Hiddify, Clash/mihomo, naive и другие) слушают порты на `127.0.0.1`. Понимает и HTTP-прокси, и SOCKS5.

Свой VPN-клиент можно научить сообщать порт: при запуске он пишет адрес прокси (`127.0.0.1:2080` или `socks5://127.0.0.1:10808`) первой строкой в `/run/yozmor/local_proxy.txt`, при выходе удаляет. Или впиши часть имени его программы в `notify.conf`: `PROXY_CLIENTS=myclient`.

## Команды без окна

```bash
sudo ygg-watchdog tick                          # одна проверка
sudo ygg-watchdog status                        # коротко о состоянии
sudo ygg-watchdog diagnose                      # почему нет связи
sudo ygg-watchdog set-region Россия Владивосток # регион поездки (номер, slug или по-русски)
sudo ygg-watchdog remove-region
sudo ygg-watchdog set-home-region russia Moscow # домашний регион; clear - снять
sudo ygg-watchdog add-main-peer tls://host:port
sudo ygg-watchdog remove-main-peer 2
sudo ygg-watchdog verify-peer tls://host:port   # подключить на пару секунд и показать результат
sudo ygg-watchdog add-device ThinkPad 200::1 tls://общий:пир
sudo ygg-watchdog diagnose-device ThinkPad
sudo ygg-watchdog restart-yggdrasil-delayed 15  # безопасно, если сидишь по Yggdrasil
sudo ygg-watchdog stop-timer | start-timer
sudo ygg-watchdog check-update | apply-update
sudo ygg-watchdog find-best-peers --count 3 [--add]   # полный перебор по задержке (долго)
ygg-watchdog help                               # все команды
```

Подробный лог проверки: `sudo ygg-watchdog -v tick`. Лог: `tail -f ~/ygg-watchdog/watchdog.log`.

| `ygg-watchdog` | программа (собирается `build.sh`) |

| `state.txt`, `watchdog.log`, `events.log`, `history.log`, `peer_stats.txt`, `peers_cache/` | состояние, логи, история и кэш — создаются сами |
