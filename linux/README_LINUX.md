# Yggdrasil Watchdog (Linux) - инструкция

## Что это

Автоматика, которая следит за связью Yggdrasil и сама чинит её при
проблемах - по нарастающей, от простой замены пира до аварийного
перебора всех известных пиров. Плюс - ручное меню для управления
регионами, устройствами, VPN и обновлениями, когда нужно вмешаться
самому.

## Что работает автоматически, без твоего участия

Раз в 3 минуты systemd-таймер запускает проверку (`tick`):

- **Аварийный режим по батарее** проверяется первым делом (ноутбуки) -
  если заряд ≤5% и не на зарядке, все остальные проверки этого тика
  пропускаются целиком (одно уведомление на вход, одно на выход; на
  машинах без батареи проверка просто не применяется)
- Раз в сутки - тихая проверка обновлений на GitHub (только
  уведомление, ничего не скачивает сама)
- Если все основные пиры легли - ищет замену: сначала в egress-регионе
  (автоматически по IP через GeoIP, кэш на час - корректно учитывает
  VPN, если он держит маршрут по умолчанию), иначе в домашнем регионе
  (ручной fallback), проверяет кандидата настоящим рукопожатием,
  добавляет как резервного
- Если обычный поиск не помог - крайняя мера: аварийный (SOS) перебор
  ВСЕХ пиров ВСЕХ стран, ограниченный по времени за один тик,
  возобновляемый через курсор (следующий тик продолжает с того же
  места), с 12-часовой паузой после полного прохода без результата
- Как только основной снова жив - резервные убираются
- Если включён региональный режим - следит за региональными пирами
  вместо основных (полностью игнорирует основные, пока регион активен)
- Если пропал интернет вообще (не только пиры) - не тратит время на
  бессмысленный поиск, ждёт восстановления и сообщает об этом в лог
- Если связь в порядке - проверяет добавленные вручную устройства
  (ноутбуки, не телефон); при подтверждённой недоступности проверяет,
  не сам ли Yggdrasil на этой машине перегружен (а не нагрузка машины
  вообще - через отзывчивость `yggdrasilctl`), и если да - перезапускает
  службу

Проверить, что таймер жив:
```bash
systemctl status ygg-watchdog-tick.timer
systemctl list-timers ygg-watchdog-tick.timer
```

## Установка

```bash
git clone https://github.com/Yozmor/ygg-watchdog.git /tmp/ygg-src
mkdir -p ~/ygg-watchdog
cp -r /tmp/ygg-src/linux/. ~/ygg-watchdog/
rm -rf /tmp/ygg-src
cd ~/ygg-watchdog
sudo ./install.sh
```

Программа ставится и работает в `~/ygg-watchdog`. `install.sh` прописывает эту папку в systemd-таймер, включает его и добавляет команду `ygg-watchdog`. Для обновления выполни те же команды: файлы программы заменятся, а `notify.conf`, состояние и логи сохранятся (либо используй `apply-update` после первой установки - см. раздел «Обновления» ниже). Выключить автопроверку: `sudo ./install.sh --remove`.

## Как запустить панель управления вручную

```bash
ygg-watchdog
```

(или `cd ~/ygg-watchdog && sudo python3 -B watchdog_daemon.py menu`)

Появится меню:

```
================================================
        YGG WATCHDOG
================================================

  1 - Проверить сейчас (tick)
  2 - Показать статус
  3 - Добавить регион (страна + город)
  4 - Убрать региональный режим
  5 - Показать основные пиры
  6 - Добавить основной пир
  7 - Удалить основной пир
  8 - Перезапустить Yggdrasil СЕЙЧАС (обрывает сессии по Yggdrasil!)
  9 - Перезапустить Yggdrasil С ЗАДЕРЖКОЙ (безопасно при SSH по Yggdrasil)
  10 - Остановить автоматические проверки (systemd-таймер)
  11 - Включить автоматические проверки обратно
  12 - Задать домашний регион (запасной вариант для резервных пиров)
  13 - Показать мониторимые устройства
  14 - Добавить устройство в мониторинг
  15 - Убрать устройство из мониторинга
  16 - Одобрить свою команду управления VPN (продвинутый уровень)
  17 - Снять одобрение VPN-команды (вернуться на базовый уровень)
  18 - Проверить обновления
  19 - Установить обновление
  0 - Выход
```

### Пункт 1 - Проверить сейчас
То же самое, что делает таймер каждые 3 минуты, но сразу, не дожидаясь.
Полезно, чтобы проверить эффект сразу после ручной правки.

### Пункт 2 - Статус
Показывает: путь к конфигу, режим (normal/regional), основные/резервные/
региональные пиры, домашний и текущий egress-регион, мониторимые
устройства, активен ли аварийный режим по батарее.

### Пункт 3 - Добавить регион
Спрашивает страну и город пошагово:
1. Покажет список стран (с GitHub, живой список) - вводишь номер
2. Покажет список городов именно этой страны (из базы GeoNames,
   с реальными координатами) - вводишь номер, или просто Enter, если
   нужен пир из любого города страны
3. Запустит поиск **в фоне** (отдельный процесс) - панель сразу
   возвращает управление, не ждёт. Настоящая проверка (рукопожатие)
   может занять от нескольких секунд до пары минут в зависимости от
   числа кандидатов.

Пока региональный режим активен - основные пиры полностью
игнорируются (это осознанное правило, не баг). Можно вызывать пункт 3
несколько раз подряд, чтобы добавить сразу несколько регионов -
предыдущие не потеряются.

Прогресс фонового поиска смотри в логе (см. ниже).

### Пункт 4 - Убрать региональный режим
Снимает **все** региональные пиры разом, возвращает обычный режим
слежения за основными.

### Пункты 5-7 - Основные пиры
- **5**: показывает список из `yggdrasil.conf`
- **6**: добавляет новый URI прямо в конфиг (спросит адрес)
- **7**: покажет список и попросит номер для удаления

**Важно**: правки конфига вступают в силу только после перезапуска
службы (пункты 8/9) - Yggdrasil читает конфиг один раз при старте.

### Пункты 8-9 - Перезапуск службы
- **8** - сразу. Если ты подключён к серверу через сам Yggdrasil
  (например SSH по Yggdrasil-адресу) - твоя же сессия оборвётся в
  процессе.
- **9** - с задержкой (по умолчанию 10 секунд, можно другую). Команда
  уходит по ещё живому каналу, а сам перезапуск происходит через
  несколько секунд - успеваешь отключиться/переключиться на другой
  канал до того, как соединение прервётся.

**Используй пункт 9, если не уверен, как именно сейчас подключён.**

### Пункты 10-11 - Автоматические проверки
- **10**: остановить и выключить systemd-таймер (проверки по расписанию
  прекращаются, ручной `tick` всё равно работает)
- **11**: включить таймер обратно

### Пункт 12 - Домашний регион
Постоянный ручной fallback для поиска резервных пиров - используется,
только если автоматическое определение egress-региона через GeoIP не
сработало (нет сети наружу, сервисы недоступны). Пустой ввод снимает
домашний регион.

### Пункты 13-15 - Устройства для мониторинга
Добровольно добавленные ноутбуки (НЕ телефон - решили специально не
подключать), проверяются только после подтверждённой основной
связности:
- **13**: список с текущим статусом (доступно/недоступно)
- **14**: добавить (спросит имя и Yggdrasil-адрес)
- **15**: удалить (покажет список, спросит имя)

### Пункты 16-17 - VPN (продвинутый уровень)
По умолчанию (базовый уровень) программа в VPN-клиент не лезет вообще -
только предупреждает в логе/Telegram, если похоже, что проблема в нём.
Продвинутый уровень включается одобрением СВОЕГО скрипта перезапуска:
- **16**: одобрить скрипт (укажи путь) - сохраняется путь и SHA-256
  содержимого на момент одобрения; перед КАЖДЫМ запуском хэш
  пересчитывается и сверяется, при любом изменении скрипта запуск
  отказывается (защита от тихой подмены)
- **17**: снять одобрение, вернуться на базовый уровень

### Пункты 18-19 - Обновления
Программа и сама, раз в сутки, тихо проверяет GitHub и только
уведомляет, если есть новая версия - ничего не скачивает
автоматически:
- **18**: проверить вручную прямо сейчас
- **19**: скачать и поставить новую версию - новые файлы сначала
  проходят компиляционную самопроверку (`py_compile`), и только если
  она прошла успешно, заменяют старые; при любом сбое - автоматический
  откат на сохранённую резервную копию, ничего не остаётся наполовину
  обновлённым

## Полный перебор по задержке (`find-best-peers`)

Отдельная от watchdog-логики команда для разового ручного подбора:
перебирает кандидатов из ВСЕХ стран, измеряет настоящую задержку
рукопожатия и возвращает лучших. Долгая (перебор большой), запускать
руками, не в фоновом тике:

```bash
sudo python3 watchdog_daemon.py find-best-peers --count 3 --per-country 1
sudo python3 watchdog_daemon.py find-best-peers --count 3 --add   # сразу добавить как основные
```

## Уведомления в Telegram

Присылает push-уведомления о значимых событиях:

- **Все основные пиры легли, найден резервный** - какие основные
  отвалились, какой резервный добавлен взамен (включая найденный через
  аварийный SOS-перебор)
- **Основные пиры снова живы** - какие резервные удалены
- **Пропадал интернет целиком** (не только Yggdrasil) - одно сообщение
  с обоими точными временами
- **Устройство недоступно / снова на связи** - с указанием, сколько
  было недоступно
- **Вход/выход из аварийного режима по батарее**
- **SOS-перебор начался / нашёл пира / завершился без результата**
- **Доступна новая версия на GitHub**

Рутинные проверки ("всё в порядке, без изменений") в Telegram **не**
шлются - только реальные события, чтобы не спамить.

### Настройка (один раз)

1. Открой `@BotFather` в Telegram, отправь `/newbot`, следуй
   инструкциям - получишь токен вида `123456:ABC-DEF...`
2. Напиши что-нибудь своему новому боту (любое сообщение)
3. Открой в браузере:
   `https://api.telegram.org/bot<ТВОЙ_ТОКЕН>/getUpdates`
4. В ответе найди число в поле `"chat":{"id": ЭТО_ЧИСЛО}`
5. Переименуй `notify.conf.example` в `notify.conf` (та же папка, что
   `watchdog_daemon.py`), впиши токен и chat_id:
   ```
   BOT_TOKEN=123456:ABC-DEF...
   CHAT_ID=987654321
   ```

Если файла `notify.conf` нет вообще, или в нём не хватает одного из
полей - уведомления просто молча выключены, ничего не ломается и не
падает с ошибкой.

**Если у тебя два устройства (например Linux-сервер и Windows-ноутбук) шлют
уведомления в одного и того же бота** - в каждом сообщении автоматически
указывается имя устройства-отправителя (реальное имя хоста), чтобы
не путать, откуда пришло.

## Логи

```bash
tail -f ~/ygg-watchdog/watchdog.log
```

По умолчанию видны только осмысленные события (что произошло на
каждой проверке, включая "без изменений", а не только аномалии). Для
подробностей (что именно проверялось, почему принято решение):

```bash
sudo python3 -B ~/ygg-watchdog/watchdog_daemon.py -v tick
```

Логи старше 14 дней автоматически подчищаются, файл не растёт
бесконечно.

## Проверка после переноса на новый сервер / после обновления файлов

```bash
sudo python3 -B ~/ygg-watchdog/selftest.py
```

Пройдёт ряд проверок: файлы на месте, синтаксис, реальный запрос к
GitHub, реальная проверка базы городов (расстояние Москва-Владивосток),
реальное рукопожатие с живым кандидатом, статус таймера. Все пункты
должны быть `OK`.

## Файлы проекта

| Файл | Назначение |
|---|---|
| `peer_database.py` | GitHub-пиры, база городов с координатами, настоящее рукопожатие |
| `watchdog_core.py` | Логика принятия решений, состояние, правка конфига, перезапуск службы |
| `watchdog_daemon.py` | Командная строка + интерактивное меню |
| `geoip.py` | Определение egress-страны по IP (несколько провайдеров по очереди) |
| `device_monitor.py` | Мониторинг устройств (пинг с debounce, проверка отзывчивости Yggdrasil) |
| `battery.py` | Чтение заряда батареи для аварийного режима |
| `vpn_hook.py` | Одобрение и запуск своего VPN-скрипта с привязкой к SHA-256 |
| `auto_update.py` | Проверка версии на GitHub, скачивание и применение обновления с откатом |
| `cities.dat` | База городов GeoNames (обязателен, без него региональный поиск по координатам не работает) |
| `notify.conf` | Токен/chat_id для уведомлений в Telegram (необязателен - без него уведомления просто выключены) |
| `vpn_hook_approval.json` | Одобренный VPN-скрипт и его SHA-256 (появится после `approve-vpn-command`) |
| `selftest.py` | Самопроверка после установки/переноса/обновления |
| `ygg-watchdog-tick.service` / `.timer` | systemd-таймер, автоматическая проверка каждые 3 минуты |

## Команды напрямую (без меню), если нужна автоматизация/скрипты

```bash
cd ~/ygg-watchdog
sudo python3 watchdog_daemon.py tick                          # один цикл проверки
sudo python3 watchdog_daemon.py status                        # статус
sudo python3 watchdog_daemon.py list-countries                # список стран
sudo python3 watchdog_daemon.py list-cities russia            # города страны (номер или slug)
sudo python3 watchdog_daemon.py add-region russia Vladivostok # регион напрямую (без меню)
sudo python3 watchdog_daemon.py remove-region
sudo python3 watchdog_daemon.py set-home-region russia        # домашний регион ("clear" или без аргумента - снять)
sudo python3 watchdog_daemon.py list-main-peers
sudo python3 watchdog_daemon.py add-main-peer tls://host:port
sudo python3 watchdog_daemon.py remove-main-peer 2
sudo python3 watchdog_daemon.py restart-yggdrasil
sudo python3 watchdog_daemon.py restart-yggdrasil-delayed 15
sudo python3 watchdog_daemon.py stop-timer                    # выключить автопроверку
sudo python3 watchdog_daemon.py start-timer                   # включить обратно
sudo python3 watchdog_daemon.py list-devices
sudo python3 watchdog_daemon.py add-device ThinkPad 200:1234:abcd::1
sudo python3 watchdog_daemon.py remove-device ThinkPad
sudo python3 watchdog_daemon.py approve-vpn-command /usr/local/bin/vpn-restart.sh
sudo python3 watchdog_daemon.py clear-vpn-command
sudo python3 watchdog_daemon.py check-update
sudo python3 watchdog_daemon.py apply-update
sudo python3 watchdog_daemon.py find-best-peers --count 3 --per-country 1 [--add]
```

## Про графический ярлык (двойной клик)

Пробовали - не завелось на этой конкретной установке (`Terminal=true`
в `.desktop`-файле не находит терминал, хотя `xfce4-terminal`
формально есть в системе - похоже, GNOME его не видит как
зарегистрированный терминал по умолчанию). Решили не тратить на это
время - панель полностью рабочая через обычный терминал, этого
достаточно.
